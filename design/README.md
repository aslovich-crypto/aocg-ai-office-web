# Вендорная копия дизайн-системы

`theme.mjs` — машинная выгрузка токенов из проекта Claude Design
**«AOCG AI Office Design System»** (`b58d4af2-2ba2-49ce-93d2-236525fb0ed4`).
Собирается там скриптом `tools/build-tokens.js` из `colors_and_type.css`
(блок `:root`) — единственного места рождения цвета в системе.

**Файл не редактируется руками.** Он сверяется побайтно контрольной суммой
из `source.json` на каждом прогоне `npm run lint`. Любая правка здесь означает,
что копия перестала быть копией, и проверка упадёт.

`source.json` — происхождение копии: когда подтянули, из какого проекта и файла,
контрольная сумма, число токенов. **Дата здесь и только здесь** — в этом README
она намеренно не дублируется, иначе разъедется (сегодняшний урок с CLAUDE.md).
Порога «копия старше N дней» нет и не будет: время не связано с тем, изменилась
ли палитра — копия полугодовой давности верна, если ДС не менялась, а вчерашняя
устарела, если поправили час назад. Предупреждение по календарю обучает себя
игнорировать. Реальная проверка свежести — `node design/freshness.mjs` (задача **T12**).

```bash
# канон достаёт агент коннектором и кладёт во временный файл
node design/freshness.mjs --canon /tmp/colors_and_type.css
node design/freshness.mjs --canon /tmp/canon.css --export /tmp/theme.mjs
```

Скрипт сверяет **токены, а не байты**: комментарии и отступы в каноне
меняются сами по себе, и тревога по ним обучала бы себя игнорировать —
та же болезнь, что у сигнала по дате. И отдельно различает **«канон
недоступен»** (код 2 — проверка НЕ выполнялась) и **«расхождений нет»**
(код 0): два разных факта, которые выглядят одинаково успокаивающе.

**Артефакта три, а не два** (замер 08.08.2026): канон `colors_and_type.css`
→ выгрузка `export/theme.mjs` в самом проекте ДС → наша копия. Расхождение
может сидеть на любом стыке, и лечится по-разному: между каноном и выгрузкой
— пересобрать выгрузку в проекте ДС (мы этого сделать не можем), между
выгрузкой и копией — подтянуть файл сюда. Скрипт называет стык.

## Почему копия, а не чтение из ДС на лету

Доступ к проекту Claude Design идёт через коннектор с интерактивной
авторизацией. В CI и на сборке площадки его нет. Сборка, зависящая от внешнего
сервиса и чужой сессии, ложится в самый неподходящий момент — поэтому источник
лежит в репозитории.

## Где лежит выгрузка ДС — `design/handoff/`

**Постоянное место, БЕЗ даты в имени, НЕ в git.** Сюда распаковывается
handoff-архив из проекта Claude Design; новая выгрузка кладётся туда же,
поверх старой.

⚠️ **Почему не в git.** Выгрузка — источник, а не артефакт проекта: 149 файлов,
12 МБ, из них нужны единицы. Нужное **вендорится отдельными файлами**, которые
в git есть и под сторожем контрольных сумм:

| файл | что это | сумма стережётся |
|---|---|---|
| `design/theme.mjs` | 94 токена, палитра | `design/source.json` |
| `design/aocg-mark.svg` | контур Λ | `scripts/check-app-icon.mjs` |
| `design/app-icon-1024.png` | иконка, крупная | `design/app-icon.source.json` |
| `public/apple-touch-icon.png` | иконка 180×180 | `design/app-icon.source.json` |

**`handoff/` им не замена, а происхождение.** Файл в git — то, что работает;
выгрузка — то, откуда он взят и с чем сверяется.

⚠️ **Почему без даты в имени.** Каталог вида «AOCG AI Office Design System
29082026» пришлось бы заносить в игноры заново при каждой выгрузке, а старое
правило осталось бы навсегда — игнор под конкретный файл не переживает
следующий файл. Постоянное имя решает это один раз.

⚠️ **От чего это лечит, случай 29.08.2026.** Канонная иконка искалась тремя
кругами: сначала собрана из кода, потом в архиве нашлась спецификация
(`preview/brand-appicon.html`), потом — сам архив с готовыми PNG. Три круга
и три сообщения владельцу ушли на то, чтобы найти каталог. **С постоянным
путём искать больше не надо: он известен заранее.**

⚠️ **ВНУТРИ ВЫГРУЗКИ ЛЕЖИТ ОТМЕНЁННЫЙ МАКЕТ — 30.08.2026.**

`handoff/ui_kits/mobile-app/` — **ОТМЕНЁННЫЙ** макет настроек: шесть плоских
вкладок «Аккаунт · Организация · Лицензии · Пользователи · Сервисы · Общие».
**Действующий канон профиля — `handoff/templates/profile/Профиль.html`**:
список-хаб, три группы, семь пунктов.

Из кита пришёл дубль **«Личные данные»**: там так называлась секция ВНУТРИ
«Аккаунта», а в действующем каноне это ГРУППА хаба — и слово оказалось
в приложении в двух ролях сразу. Нашёл владелец глазами, не проверка.
**Сколько ещё мест в коде живут по этому киту — не измерено, см. T109.**

⚠️ Почему предупреждение здесь, а не только в самой папке. В папке лежит
`ОТМЕНЁН.md`, но **весь `design/handoff/` в игноре** — тот файл живёт только
на машине, где делали выгрузку. На другой машине его не будет, а этот README
в git и его читают. **Источник истины — здесь.**

Каталог в `.gitignore` (строка `design/handoff/`) и в `globalIgnores`
конфига eslint — иначе `npm run lint` краснеет на чужом коде из выгрузки
(замер: 133 ошибки из 11 файлов).

## Как обновить

1. Попросить агента подтянуть свежий `export/theme.mjs` из ДС коннектором.
2. Он кладёт файл сюда, обновляет `source.json` (сумма + дата) и показывает diff.
3. Diff смотрит человек: смена палитры — решение, а не событие. Изменение
   значения токена меняет вид приложения во всех местах сразу.
4. Коммит вместе с правками, которые потребовались из-за смены.

Автоматического обновления нет намеренно.

## Что дальше в коде

`src/lib/theme.js` ре-экспортирует отсюда `theme` и держит объект `C` —
старые имена как алиасы канонных токенов (`silver: theme.border` и т.д.),
чтобы 480 существующих обращений не пришлось править одним махом.
Новый код пишет канонные имена: `theme.fg1`, `theme.errorBd`.

Порядок работ и остаток долга — задача **T10** в трекере бэкенда
(`docs/TASKS.md` репозитория aocg-ai-office).

## Состав выгрузки

88 токенов, из них 70 цветов. Группы: бренд, нейтральные, «на тёмном»,
семантические статусы (success/warning/info/planned/error), 11 пар категорий,
палитра диаграмм, вишнёвая лестница, шрифты, радиусы, тени, отступы, анимации.
Помимо `theme` файл экспортирует `colors` (только цвета) и `cssVar(key)` —
`cssVar("cherryHover") → "var(--cherry-hover)"` для мест, где удобнее
CSS-переменная.
