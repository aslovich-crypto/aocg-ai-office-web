# Вендорная копия дизайн-системы

`theme.mjs` — машинная выгрузка токенов из проекта Claude Design
**«AOCG AI Office Design System»** (`b58d4af2-2ba2-49ce-93d2-236525fb0ed4`).
Собирается там скриптом `tools/build-tokens.js` из `colors_and_type.css`
(блок `:root`) — единственного места рождения цвета в системе.

**Файл не редактируется руками.** Он сверяется побайтно контрольной суммой
(`theme.mjs.sha256`) на каждом прогоне `npm run lint`. Любая правка здесь
означает, что копия перестала быть копией, и проверка упадёт.

## Почему копия, а не чтение из ДС на лету

Доступ к проекту Claude Design идёт через коннектор с интерактивной
авторизацией. В CI и на сборке Railway его нет. Сборка, зависящая от внешнего
сервиса и чужой сессии, ложится в самый неподходящий момент — поэтому источник
лежит в репозитории.

## Как обновить

1. Попросить агента подтянуть свежий `export/theme.mjs` из ДС коннектором.
2. Он кладёт файл сюда, пересчитывает `theme.mjs.sha256` и показывает diff.
3. Diff смотрит человек: смена палитры — решение, а не событие. Изменение
   значения токена меняет вид приложения во всех местах сразу.
4. Коммит вместе с правками, которые потребовались из-за смены.

Автоматического обновления нет намеренно.

## Что дальше в коде

`src/lib/theme.js` ре-экспортирует отсюда `theme` и держит объект `C` —
старые имена как алиасы канонных токенов (`silver: theme.border` и т.д.),
чтобы 480 существующих обращений не пришлось править одним махом.
Новый код пишет канонные имена: `theme.fg1`, `theme.errorBd`.

Порядок работ и остаток долга — задача **T10** в трекере бэкенда
(`docs/TASKS.md` репозитория aocg-ai-office).

## Состав выгрузки

88 токенов, из них 70 цветов. Группы: бренд, нейтральные, «на тёмном»,
семантические статусы (success/warning/info/planned/error), 11 пар категорий,
палитра диаграмм, вишнёвая лестница, шрифты, радиусы, тени, отступы, анимации.
Помимо `theme` файл экспортирует `colors` (только цвета) и `cssVar(key)` —
`cssVar("cherryHover") → "var(--cherry-hover)"` для мест, где удобнее
CSS-переменная.
