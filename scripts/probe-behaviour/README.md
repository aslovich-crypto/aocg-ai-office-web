# Проба поведения — не сторож

Поднимает **настоящее приложение** (`src/App.jsx` целиком), подставляет
ответы сети и **жмёт кнопки по сценарию**, печатая, на каком экране
оказалась.

```
node_modules/.bin/vite build   --config scripts/probe-behaviour/vite.config.mjs
node_modules/.bin/vite preview --config scripts/probe-behaviour/vite.config.mjs --port 5286
Chrome --headless --dump-dom http://localhost:5286/  →  <div id="ЗАМЕР">
```

## ⚠️ Зачем она появилась

30.08.2026 владелец сказал: «вышел, зашёл — снова попадаю в профиль,
твоя правка не сработала», а сторож `check-logout-return.mjs` был
**зелёным**. Сторож читает исходник и проверяет, что **проводка
написана** — он не видит, что произошло на экране.

Проба показала: поведение работает.

```
① вход выполнен .............. Главная
② открыт профиль ............. Профиль
③ после выхода ............... ЭКРАН ВХОДА
④ после повторного входа ..... Главная
```

Расхождение оказалось не в коде: правка `e59c88c` не была запущена
в прод. Но выяснилось это **прибором**, а не спором.

## ⚠️ Граница чтения исходника — где она на самом деле

Читать исходник законно там, где у поведения **нет наблюдаемого
следствия**. Возврат после выхода наблюдаем — человек видит экран.
Значит и проверять надо наблюдением. Формулировка «здесь чтение
исходника законно» была ошибкой агента.

## Чего здесь нет

Это **разовая проба, а не сторож**: в `npm run lint` не включена,
мутаций на ней не гоняно. Сделать постоянной — отдельная работа.

## Две ловушки, на которых она сама спотыкалась

1. **`кнопкаПо("Войти")` по совпадению начала** кликала «Войти через
   Яндекс ID». Нужно точное совпадение.
2. **React не видит `input.value`, выставленное напрямую** — у него свой
   сеттер на прототипе. Без обхода поля остаются пустыми для состояния,
   и проба молча показывает «экран входа», как будто вход сломан.
