# Прогон вёрстки по ширинам

Разовый инструмент. Поднимает браузер, логинится, обходит 16 сочетаний
«ширина × экран» и снимает все показания сторожа переполнения плюс скриншот
каждого состояния.

Ширины: **320 · 360 · 375 · 430** (480 — предел колонки, проверен отдельно).
Экраны: **Главная · Сводка · Чеки · Отчёты**.
На «Чеках» и «Отчётах» замер идёт в трёх положениях прокрутки — верх,
середина, низ, — потому что плавающая кнопка прячется при прокрутке и один
кадр показал бы либо пустоту, либо случайное попадание.

## Запуск

```
cd tools/layout-audit
npm run setup          # один раз: зависимости + Chromium
npm run audit
```

Результат — в `out/`: `report.md` и скриншоты. Папка в `.gitignore`.

## Доступы

Читаются из `.env` (сначала корневого, затем локального). Образец —
`.env.example` в корне репозитория:

```
AUDIT_URL=            # пусто = локальная сборка http://localhost:4173
AUDIT_EMAIL=
AUDIT_PASSWORD=
```

В git креды не попадают: `.env` в `.gitignore`.

**По умолчанию гоним против ЛОКАЛЬНОЙ сборки**, а не прода: так проверяется
код из рабочего дерева, то есть ДО пуша. Запросы к API всё равно уходят
на прод-бэкенд. Перед запуском:

```
npm run build && npx vite preview --port 4173
```

Чтобы проверить задеплоенное — задайте `AUDIT_URL`.

## Как читать таблицу

Ячейка: `документ/экран · вылезли(первопричин)/шире родителя/обрезано/срезан
предком/перекрыто С ТЕКСТОМ`.

- **документ > экрана** — есть горизонтальная прокрутка, уезжает весь каркас;
- **вылезли за экран** — считаются только ПЕРВОПРИЧИНЫ: элемент вылез,
  а его родитель нет. Потомки, унаследовавшие беду, не в счёт;
- **шире родителя** — торчит из своего контейнера;
- **обрезано** — режет сам себя, без многоточия (многоточие — намеренное);
- **срезан предком** — режет предок через любую глубину;
- **перекрыто С ТЕКСТОМ** — плавающий элемент реально лежит СВЕРХУ
  (подтверждено `elementFromPoint`) и закрывает содержимое с собственным
  текстом. Пустые оболочки в итог не идут.

Для «Чеков» и «Отчётов» берётся ХУДШЕЕ из трёх положений прокрутки.

## Самопроверка

Перед основным прогоном запускается тонкая проба **+5px** (`#overflow-test-thin`).
Не поймана — прогон падает и таблицу не печатает.

Тонкая, а не грубая +120px, намеренно: грубая доказывает лишь то, что грубый
случай ловится. Мы это уже проходили — сторож пропускал реальные 30-40px
и при этом уверенно ловил синтетические 120. Правило T11.

## Сколько запросов делает прогон

Наш ограничитель частоты — **60 запросов в минуту с одного IP** (задача S-27).
Прогон в него влезать обязан, иначе он банит сам себя: 03.08.2026 три прогона
подряд привели к 429 «IP temporarily banned», приложение открывалось, данные
не грузились, и отчёт напечатал нули по всем экранам — что читалось как победа.

Арифметика, чтобы паузу не подбирали на ощупь:

| действие | запросов | сколько раз | итого |
| --- | --- | --- | --- |
| вход | ~2 | 1 | 2 |
| полная загрузка страницы (me, receipts, cards, users, категории, организация, отчёты) | ~8 | 4 (по одной на ширину) | 32 |
| переключение экрана кликом | ~0-1 | 16 | ~8 |
| **всего** | | | **~42** |

Загрузок именно четыре, а не шестнадцать: страница грузится один раз на ширину,
дальше экраны переключаются кликами по нижнему меню. До этой правки было
16 полных перезагрузок — вчетверо больше, и лимит выбивался.

Пауза между экранами — 900 мс: и на догрузку данных, и на запас по лимиту.

## Отказ вместо нулей

Перед КАЖДЫМ сочетанием (не один раз в начале — бан прилетает в середине серии)
проверяется пригодность замера:

- на странице нет признаков отказа сервера («temporarily banned», «Слишком
  много запросов», 429);
- на денежных экранах («Главная», «Сводка», «Чеки») есть хотя бы одна сумма
  в рублях — значит данные доехали;
- «Отчёты» проверяются только на отказ: пустой список отчётов — законное
  состояние.

Не выполнено — прогон падает и отчёт НЕ печатает. Нули при пустом экране
читаются как результат, поэтому лучше не печатать ничего.

В шапке отчёта есть строка «данные загрузились: да/нет» и число сумм,
видимых на «Чеках»: по архивному отчёту через месяц будет понятно,
настоящий он или пустой.

## Чего инструмент НЕ даёт

Записано, чтобы через месяц зелёная таблица не начала значить больше,
чем она значит.

- **Headless Chromium — это не Safari на iPhone.** Движки разные, и часть
  наших прошлых сюрпризов родилась именно в Safari.
- **Нет `safe-area-inset`.** У нас на нём стоят отступы шапки, нижнего меню
  и положение плавающей кнопки. Значит полоса кнопки в прогоне СМЕЩЕНА
  относительно реального телефона, и перекрытия могут находиться не там, где
  на устройстве.
- **Другое поведение `dvh`** при появлении и скрытии панели браузера
  на iOS — высоты в прогоне стабильнее, чем в жизни.
- **Другие шрифтовые метрики.** Ширина текста считается иначе, а почти все
  наши переполнения упирались именно в ширину подписей.
- **Крупный шрифт и зум страницы не воспроизводятся.** Сегодняшний дефект
  проявился при 383 CSS-px — это не штатная ширина устройства, а результат
  увеличенного масштаба. Прогон меряет штатные ширины.
- **«Выглядит криво» не ловится в принципе.** Счётчики про геометрию:
  элемент шире родителя или нет. Композиция, читаемость, попадание
  в дизайн-линию — только глазами по скриншотам.

Инструмент снимает класс «элемент шире родителя на такой-то ширине»
и делает это на четырёх ширинах за один прогон вместо ручного перебора.
Проверку на устройстве он не заменяет.
