# Прогон вёрстки по ширинам

Разовый инструмент. Поднимает браузер, логинится, обходит 16 сочетаний
«ширина × экран» и снимает все показания сторожа переполнения плюс скриншот
каждого состояния.

Ширины: **320 · 360 · 375 · 430** (480 — предел колонки, проверен отдельно).
Экраны: **Главная · Сводка · Чеки · Отчёты**.
На «Чеках» и «Отчётах» замер идёт в трёх положениях прокрутки — верх,
середина, низ, — потому что плавающая кнопка прячется при прокрутке и один
кадр показал бы либо пустоту, либо случайное попадание.

## Запуск

Диагностика, на которой держится прогон, **в боевую сборку не попадает**
(T19, 08.08.2026): модуль подключается только при `VITE_DIAG=1`, иначе его
в бандле нет вовсе. Поэтому режима два, и по умолчанию — первый.

### Режим 1 — ЛОКАЛЬНАЯ СБОРКА (основной)

```
# в корне фронтенда
VITE_DIAG=1 VITE_API_URL= npm run build
npm run preview                # отдаёт на http://localhost:4173

# в другом окне
cd tools/layout-audit
npm run setup                  # один раз: зависимости + Chromium
npm run audit                  # без AUDIT_URL идёт на localhost:4173
```

**Две переменные, и обе обязательны.** `VITE_DIAG=1` кладёт в сборку
диагностику (в боевую она не попадает, T19). `VITE_API_URL=` — ПУСТОЕ
значение, оно переводит запросы на свой origin, откуда их забирает прокси
Vite и отправляет на бэкенд (T20). Без второй переменной сборка пойдёт
прямо на боевой адрес, а он чужой origin — CORS-whitelist (S-19) не пустит,
и экраны придут пустыми.

Почему основной: прод остаётся чистым всегда, а «забыл выключить флаг»
становится невозможным — самая вероятная из наших ошибок просто не может
случиться.

⚠️ **ПОБОЧНЫЙ ЭФФЕКТ ВХОДА: ПРОГОН ЛОГИНИТСЯ ПО-НАСТОЯЩЕМУ, И ЭТО ПИШЕТ
В БОЕВУЮ БАЗУ.** Успешный вход выполняет
`UPDATE users SET failed_attempts=0, locked_until=NULL, last_login_at=NOW()`.
Неудачный — НАОБОРОТ: увеличивает счётчик попыток, и **на пятой неверной
попытке аккаунт блокируется на 15 минут**. То есть опечатка в
`AUDIT_PASSWORD` блокирует ту учётную запись, под которой гоняете, посреди
работы — а причина будет выглядеть как «вход сломался», хотя сломал его
прогон. Ничего другого прогон не пишет: он только логинится, переключает
вкладки и прокручивает; чеки, отчёты и категории не трогает.

**Заведите для прогона ОТДЕЛЬНУЮ учётную запись,** а не свою рабочую.
Причины две: блокировка на 15 минут не заденет живую работу, и
`last_login_at` рабочего человека не будет обновляться роботом — а это
поле однажды понадобится как признак активности. Роль подойдёт минимальная
из тех, что видят нужные экраны.

### Режим 2 — ПО ПРОДУ (исключение)

Нужен, только если замер обязан идти по продовым данным.

```
# 1. в панели Timeweb → Переменные фронта: VITE_DIAG=1  → дождаться пересборки
# 2. cd tools/layout-audit && AUDIT_URL=https://<прод> npm run audit
# 3. ⚠️ СРАЗУ УБРАТЬ VITE_DIAG из Variables и дождаться пересборки
```

⚠️ **Шаг 3 обязателен.** Пока флаг стоит, отладочная панель вооружается
на проде любым адресом с `#overflow` — кем угодно, кто знает метку.
Цена режима: две пересборки с деплоем, по документации фронта 1–2 минуты
каждая, то есть 3–5 минут ожидания плюс риск забыть выключить. Из-за
этого риска режим и объявлен исключением.

Проверить, что боевая сборка чиста, можно не глядя в панель Timeweb:

```
npm run build && npm run check:diag     # в корне фронтенда
```

Результат — в `out/`: `report.md` и скриншоты. Папка в `.gitignore`.

## Доступы

Читаются из `.env` (сначала корневого, затем локального). Образец —
`.env.example` в корне репозитория:

```
AUDIT_URL=            # пусто = локальная сборка http://localhost:4173
AUDIT_EMAIL=
AUDIT_PASSWORD=
```

В git креды не попадают: `.env` в `.gitignore`.

**По умолчанию гоним против ЛОКАЛЬНОЙ сборки**, а не прода: так проверяется
код из рабочего дерева, то есть ДО пуша. Запросы к API всё равно уходят
на прод-бэкенд — но через прокси Vite, своим origin (T20).

Команда сборки — одна, в разделе «Режим 1» выше. Здесь она намеренно
НЕ повторяется: две копии команды разъедутся, и вторая будет тихо
неправильной (у нас это уже было со строкой чека и с текстом согласия).

Чтобы проверить задеплоенное — задайте `AUDIT_URL` (режим 2).

## Как читать таблицу

Ячейка: `документ/экран · вылезли(первопричин)/шире родителя/обрезано/срезан
предком/перекрыто С ТЕКСТОМ`.

- **документ > экрана** — есть горизонтальная прокрутка, уезжает весь каркас;
- **вылезли за экран** — считаются только ПЕРВОПРИЧИНЫ: элемент вылез,
  а его родитель нет. Потомки, унаследовавшие беду, не в счёт;
- **шире родителя** — торчит из своего контейнера;
- **обрезано** — режет сам себя, без многоточия (многоточие — намеренное);
- **срезан предком** — режет предок через любую глубину;
- **перекрыто С ТЕКСТОМ** — плавающий элемент реально лежит СВЕРХУ
  (подтверждено `elementFromPoint`) и закрывает содержимое с собственным
  текстом. Пустые оболочки в итог не идут.

Для «Чеков» и «Отчётов» берётся ХУДШЕЕ из трёх положений прокрутки.

## Самопроверка

Перед основным прогоном запускается тонкая проба **+5px** (`#overflow-test-thin`).
Не поймана — прогон падает и таблицу не печатает.

Тонкая, а не грубая +120px, намеренно: грубая доказывает лишь то, что грубый
случай ловится. Мы это уже проходили — сторож пропускал реальные 30-40px
и при этом уверенно ловил синтетические 120. Правило T11.

### Стенд ветки «достижим прокруткой» (T21)

```
node tools/layout-audit/selfcheck-scroll.mjs
```

Отдельно от прогона и БЕЗ прода: поднимает `src/lib/overflowDebug.js` в пустой
странице с синтетической капсулой фильтров. Прода не требует намеренно —
иначе проверку правки пришлось бы откладывать до деплоя, а отложенная
половина мутации это ровно то место, где ошибка и живёт.

Проверяет две стороны одной ветки:

- **голос** — элемент, до которого прокруткой не добраться (проба
  `position:fixed` за пределами прокручиваемой области), обязан попасть
  в «вылезли за экран»;
- **молчание** — чип, который за краем капсулы, но достижим пальцем,
  дефектом объявляться не должен.

Почему проба именно `position:fixed`: в потоке браузер расширяет
прокручиваемую область под неё, и она становится достижимой в тот же миг
(замер: scrollWidth 400 → 504). Вне потока — не расширяет (400 → 400).
Проба сама проверяет, что scrollWidth не изменился, и говорит об этом вслух:
«проба не встала за прокрутку» и «сторож не поймал» — разные диагнозы.

## Сколько запросов делает прогон

Наш ограничитель частоты — **60 запросов в минуту с одного IP** (задача S-27).
Прогон в него влезать обязан, иначе он банит сам себя: 03.08.2026 три прогона
подряд привели к 429 «IP temporarily banned», приложение открывалось, данные
не грузились, и отчёт напечатал нули по всем экранам — что читалось как победа.

Арифметика, чтобы паузу не подбирали на ощупь:

| действие                                                                              | запросов | сколько раз            | итого   |
| ------------------------------------------------------------------------------------- | -------- | ---------------------- | ------- |
| вход                                                                                  | ~2       | 1                      | 2       |
| полная загрузка страницы (me, receipts, cards, users, категории, организация, отчёты) | ~8       | 4 (по одной на ширину) | 32      |
| переключение экрана кликом                                                            | ~0-1     | 16                     | ~8      |
| **всего**                                                                             |          |                        | **~42** |

Загрузок именно четыре, а не шестнадцать: страница грузится один раз на ширину,
дальше экраны переключаются кликами по нижнему меню. До этой правки было
16 полных перезагрузок — вчетверо больше, и лимит выбивался.

Пауза между экранами — 900 мс: и на догрузку данных, и на запас по лимиту.

## Отказ вместо нулей

Перед КАЖДЫМ сочетанием (не один раз в начале — бан прилетает в середине серии)
проверяется пригодность замера:

- на странице нет признаков отказа сервера («temporarily banned», «Слишком
  много запросов», 429);
- на денежных экранах («Главная», «Сводка», «Чеки») есть хотя бы одна сумма
  в рублях — значит данные доехали;
- «Отчёты» проверяются только на отказ: пустой список отчётов — законное
  состояние.

Не выполнено — прогон падает и отчёт НЕ печатает. Нули при пустом экране
читаются как результат, поэтому лучше не печатать ничего.

В шапке отчёта есть строка «данные загрузились: да/нет» и число сумм,
видимых на «Чеках»: по архивному отчёту через месяц будет понятно,
настоящий он или пустой.

## Состав данных и сравнимость двух прогонов (T25)

Главный способ доказать, что правка не задела лишнего, — построчно сравнить
два отчёта: «изменилось только то, что чинили». Это сравнение опирается на
допущение «данные между прогонами те же», и раньше инструмент его не проверял.

03.08.2026 между двумя прогонами появился один чек. Список «Чеков» сдвинулся,
под плавающей кнопкой оказались другие суммы — 18 новых строк в отчёте,
неотличимых от побочного эффекта правки. Разобрались запросом в прод-БД,
то есть доказательством СНАРУЖИ инструмента.

Теперь в шапке есть строка **«состав данных: чеков N (последний id X),
отчётов M»**, а отпечаток прошлого прогона лежит в `out/data-fingerprint.json`.
Если состав отличается, отчёт начинается строкой СВЕРХУ:

```
⛔ СРАВНЕНИЕ С ПРЕДЫДУЩИМ ПРОГОНОМ НЕВОЗМОЖНО: состав данных изменился.
Было: чеков 29 (последний id 50), отчётов 3
Стало: чеков 30 (последний id 51), отчётов 3
```

Сверху, а не примечанием внизу: примечание читают после того, как вывод уже
сделан. Сам отчёт при этом печатается полностью — он годен, негодно именно
СРАВНЕНИЕ с прошлым.

Отпечаток снимается из ответов, которые приложение получает само, — ни одного
лишнего запроса (см. арифметику лимита выше). Строка «данные загрузились:
сумм видно N» его не заменяет: она про то, что данные ДОЕХАЛИ, а не про то,
что они ТЕ ЖЕ.

## Чего инструмент НЕ даёт

Записано, чтобы через месяц зелёная таблица не начала значить больше,
чем она значит.

- **Headless Chromium — это не Safari на iPhone.** Движки разные, и часть
  наших прошлых сюрпризов родилась именно в Safari.
- **Нет `safe-area-inset`.** У нас на нём стоят отступы шапки, нижнего меню
  и положение плавающей кнопки. Значит полоса кнопки в прогоне СМЕЩЕНА
  относительно реального телефона, и перекрытия могут находиться не там, где
  на устройстве.
- **Другое поведение `dvh`** при появлении и скрытии панели браузера
  на iOS — высоты в прогоне стабильнее, чем в жизни.
- **Другие шрифтовые метрики.** Ширина текста считается иначе, а почти все
  наши переполнения упирались именно в ширину подписей.
- **Крупный шрифт и зум страницы не воспроизводятся.** Сегодняшний дефект
  проявился при 383 CSS-px — это не штатная ширина устройства, а результат
  увеличенного масштаба. Прогон меряет штатные ширины.
- **«Выглядит криво» не ловится в принципе.** Счётчики про геометрию:
  элемент шире родителя или нет. Композиция, читаемость, попадание
  в дизайн-линию — только глазами по скриншотам.

Первый пункт этого списка теперь дублируется СТРОКОЙ В ШАПКЕ каждого отчёта:
README читают один раз, шапку — каждый раз, а нули в таблице не должны
читаться как «проверено на телефоне».

Инструмент снимает класс «элемент шире родителя на такой-то ширине»
и делает это на четырёх ширинах за один прогон вместо ручного перебора.
Проверку на устройстве он не заменяет.

## Измеритель probe.mjs (T26)

```
node tools/layout-audit/probe-selfcheck.mjs          # ядро, синтетика, без прода
node tools/layout-audit/probe-selfcheck.mjs --prod   # + умолчания Примы на проде
```

Модуль, через который проходит любой разовый замер. Он не отдаёт элемент
молча: требует явного ожидания («мерю div со шрифтом 400 13px») и ВСЕГДА
печатает паспорт выбранного — тег, свой текст, шрифт, координаты. Флага
«подробно» нет намеренно: его выключили бы через месяц ради краткости.

Скелет замера:

```js
import {
  openApp,
  pick,
  measure,
  textWidth,
  tap,
  shot,
} from "…/tools/layout-audit/probe.mjs";

const { page, close } = await openApp({ width: 320, screen: "Чеки" });
const мета = await pick(page, {
  что: "мета карточки чека",
  найти: {
    внутри: '[role="dialog"]',
    текст: /^\d{2}\.\d{2}\.\d{4}/,
    индекс: 0,
  },
  ожидаю: { тег: "div", шрифт: "400 13px", виден: true },
});
console.log(await measure(мета));
await shot(page, "мета-320");
await close();
```

Три параметра под приложение (умолчания — Прима): `login`, `goto`, `gate`.
Финансам это будет объект на десять строк рядом со скриптом; отдельной папки
`tools/finance-audit/` заводить НЕЛЬЗЯ — это место, где заведётся вторая
копия `pick()`.
